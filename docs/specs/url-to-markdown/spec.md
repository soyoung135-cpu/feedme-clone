# URL → Markdown 변환 후 LLM으로 넘기기

관련 결정: [ui-composition](../../decisions/ui-composition.md) — 화면 구성, component 선택, 상태(loading/empty/error/success/disabled) 표현을 따릅니다. 이 기능의 control은 모두 shadcn 공식 component로 구성합니다.

## 사용자 결과

웹 페이지 URL을 붙여넣으면 본문만 깔끔한 Markdown으로 받아 보고, 그대로 복사·다운로드하거나 선택한 프롬프트와 함께 ChatGPT 또는 Claude 새 채팅으로 넘길 수 있습니다.

## 범위

1. **입력** — URL 입력 필드, 변환 버튼, 지우기 버튼. 지우기는 입력값과 결과·오류를 모두 초기 상태로 되돌립니다.
2. **변환** — 서버에서 해당 URL의 HTML을 가져와 defuddle로 본문을 Markdown으로 추출합니다.
3. **결과 확인** — 페이지 제목과 저자(있을 때만)를 헤더로 보여주고, 아래에 Markdown을 렌더링해 보여줍니다.
4. **내보내기**
   - 복사하기: 변환된 Markdown 원문을 클립보드에 복사합니다.
   - .md 다운로드: 같은 원문을 파일로 저장합니다.
   - ChatGPT로 열기 / Claude로 열기: 선택한 프롬프트(있으면) + 빈 줄 + Markdown을 새 채팅에 넘깁니다.
5. **프롬프트 선택** — 프리셋 `요약해줘` / `한국어로 번역해줘` / `쉽게 설명해줘`와 `직접 입력` 중 하나를 고르거나 아무것도 고르지 않습니다. `직접 입력`을 고르면 텍스트 입력이 나타나며, 입력값은 저장하지 않습니다(새로고침·지우기 시 사라짐).
6. **다크모드 토글** — 라이트/다크를 전환합니다.

## 수용 기준

- 유효한 기사 URL을 넣고 변환하면 제목 헤더와 렌더링된 본문이 나타나고, 저자 정보가 있으면 제목과 함께 표시됩니다. 저자가 없으면 저자 자리를 비워 두지 않고 생략합니다.
- 변환 중에는 진행 상태가 보이고 변환 버튼이 비활성화됩니다.
- URL 형식이 아니면 요청 없이 입력 오류를 보여줍니다.
- 페이지를 가져오지 못하거나(네트워크 오류, 4xx/5xx) 추출된 본문이 비어 있으면 원인을 구분한 오류 메시지를 보여주고, 이전 결과는 남기지 않습니다.
- 복사하기를 누르면 클립보드 내용이 화면에 렌더링된 원문 Markdown과 정확히 같고, 성공 피드백이 보입니다.
- 다운로드한 .md 파일 내용이 원문 Markdown과 같고, 파일 이름은 페이지 제목에서 파일명에 쓸 수 없는 문자를 제거해 만듭니다(제목이 없으면 도메인).
- 프롬프트는 ChatGPT·Claude로 열기에만 붙고, 복사·다운로드 결과에는 붙지 않습니다.
- ChatGPT·Claude로 열기(아래 전달 규칙):
  - 프롬프트+본문을 인코딩한 URL이 한도 이하이면, 새 탭에서 해당 서비스의 새 채팅이 그 내용으로 채워진 상태로 열립니다.
  - 한도를 넘으면 프롬프트+본문 전체를 클립보드에 복사한 뒤 새 채팅을 열고(이때 URL에 본문을 넣지 않음), "클립보드에 복사했어요. 채팅 입력창에 붙여넣으세요" 안내를 보여줍니다. 본문은 잘리지 않습니다.
- `직접 입력`에 텍스트가 비어 있으면 프롬프트 없이 넘깁니다.
- 지우기를 누르면 입력, 결과, 오류, 직접 입력 텍스트가 모두 초기화됩니다.
- 다크모드 토글이 전체 화면 색을 즉시 바꿉니다.
- 좁은 화면에서도 입력 → 결과 → 내보내기 순서와 모든 action이 유지됩니다.

## 확정된 제약과 이유

- **본문 추출은 defuddle을 사용합니다.** 사용자 요구사항입니다. 0.19.6에서 `defuddle/node` + linkedom 문서, `{ markdown: true }` 옵션으로 `title`, `author`, Markdown `content`가 나오는 것을 확인했습니다(Wikipedia 문서로 검증).
- **페이지 HTML은 서버에서 가져옵니다.** 브라우저에서 임의의 사이트를 직접 가져오는 것은 CORS 때문에 대부분 막힙니다.
- **LLM 전달 방식: 짧으면 URL로 채우고, 길면 클립보드로 넘깁니다.** 사용자가 정했습니다. 긴 본문을 URL에 넣으면 잘리고, 늘 클립보드만 쓰면 짧은 글도 붙여넣기를 한 번 더 해야 합니다.
- **내보내기 배치: 결과 오른쪽 사이드 패널.** 사용자가 세 안(결과 위 고정 툴바, 사이드 패널, 헤더 버튼 + 하단 고정 AI 바)을 비교하고 골랐습니다.
  - 넓은 화면에서는 렌더링된 결과 오른쪽에 패널을 두고, 스크롤해도 패널이 화면에 남아 있습니다.
  - 패널은 두 묶음으로 나눕니다. 위쪽 "내보내기"에 복사하기와 .md 다운로드를, 구분선 아래 "AI로 보내기"에 프롬프트 선택과 ChatGPT로 열기, Claude로 열기 버튼을 둡니다. 묶음을 나누는 이유는 프롬프트가 AI로 열기에만 붙는다는 점을 화면에서 드러내기 위해서입니다.
  - 프롬프트는 프리셋 세 개와 `직접 입력`을 모두 칩으로 펼쳐 보여줍니다. 칩은 하나만 선택할 수 있고, 선택된 칩을 다시 누르면 선택이 풀립니다. `직접 입력` 칩을 선택하면 칩 아래에 텍스트 입력이 나타납니다.
  - 좁은 화면에서는 패널이 결과 위로 올라가 한 열로 쌓입니다.

## 가정(변경 가능)

- 새 채팅 진입 주소는 `https://chatgpt.com/?q=` 와 `https://claude.ai/new?q=` 를 씁니다. 두 서비스가 공식으로 보장하는 기능이 아니므로 바뀔 수 있습니다.
- URL 한도는 인코딩 후 전체 URL 8,000자로 둡니다. 보수적인 값으로, 실측해 조정할 수 있습니다.
- 프롬프트는 기본적으로 아무것도 선택하지 않은 상태로 시작합니다.
- 다크모드는 처음에 시스템 설정을 따르고, 토글로 고른 값은 브라우저에 기억합니다.
- 화면은 단일 페이지입니다. 내보내기 배치 외에는 따로 프로토타입을 검토하지 않고 ui-composition 계약에 따라 구성합니다. 사용자가 흐름을 구체적으로 정했고, 나머지 레이아웃은 바꾸기 쉽기 때문입니다.

## 다루지 않는 것

- 로그인, 변환 기록 저장, 직접 입력 프롬프트 저장 — 사용자가 1회용으로 정했습니다.
- JavaScript로만 본문을 그리는 페이지(SPA)의 렌더링 — 헤드리스 브라우저가 필요해 범위가 커집니다.
- 로그인이나 결제가 필요한 페이지(페이월) 우회.
- ChatGPT·Claude 외 다른 LLM 서비스.

## 남은 위험

- ChatGPT·Claude의 `?q=` 미리 채우기가 바뀌거나 막히면 짧은 글 경로가 동작하지 않습니다. 이때 클립보드 경로로 바꾸는 것이 대안입니다.
- 서버가 사용자가 넣은 임의 URL을 가져오므로, 내부망 주소 요청(SSRF)이나 아주 큰 응답이 문제가 될 수 있습니다. 구현 시 http(s)만 허용하고 사설·로컬 주소, 응답 크기, 시간 제한을 두어야 합니다.
- SPA, 봇 차단 사이트에서는 본문이 비거나 실패할 수 있습니다(오류 메시지로 처리).
- 클립보드 쓰기는 사용자 동작 직후에만 허용되므로, 긴 글 경로에서 복사와 새 탭 열기를 같은 클릭 안에서 처리해야 합니다.
