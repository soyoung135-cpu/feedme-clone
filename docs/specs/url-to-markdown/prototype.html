React 19 서버 컴포넌트, 실무에서 6개월 써 보며 정리한 12가지

한하나 · velog.io

서버 컴포넌트를 실제 서비스에 6개월 동안 적용하면서 겪은 문제와 해결책을 정리했습니다. 공식 문서만으로는 알기 어려운 부분 위주입니다.

1. 'use client' 경계는 생각보다 위에 둬야 한다

처음에는 버튼 하나에만 'use client'를 붙였는데, 그 버튼이 쓰는 훅이 상위 트리 상태를 읽으면서 경계가 점점 올라갔습니다.

경계를 내리는 것보다 처음부터 올바른 위치에 두는 편이 훨씬 쌉니다.

2. fetch 캐시는 기본값을 믿지 말 것

Next.js 15부터 fetch의 기본 캐시 정책이 바뀌었습니다. 팀원마다 기대가 달라서 같은 화면이 어떤 날은 오래된 데이터를 보여줬습니다.

const res = await fetch(url, { next: { revalidate: 60 } });

3. 직렬화할 수 없는 props

  • Date → ISO 문자열
  • Map, Set → 배열
  • 클래스 인스턴스 → 일반 객체

저희는 경계에서 이렇게 바꾸는 규칙을 만들고 린트로 강제했습니다.

4. 스트리밍과 Suspense 경계

느린 위젯 하나 때문에 페이지 전체가 늦게 뜨는 일이 잦았습니다. 위젯마다 Suspense를 두고 스켈레톤을 따로 만드니 체감 속도가 크게 좋아졌습니다.
