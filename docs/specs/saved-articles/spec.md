# 변환한 글 저장하기와 저장한 글 목록

관련 결정: [ui-composition](../../decisions/ui-composition.md) — 새 화면(목록, 글 보기)과 control, 상태(loading/empty/error/success/disabled) 표현을 따릅니다. 이 기능의 control은 모두 shadcn 공식 component로 구성합니다.
용어: [GLOSSARY.md](../../../GLOSSARY.md)의 `변환`, `저장한 글`, `저장한 글 목록`을 씁니다.
전제: 이메일·비밀번호 로그인과 사용자별 프로필이 이미 있습니다. 이 기능은 그 로그인 위에 얹습니다.

## 사용자 결과

로그인한 사용자가 변환한 글을 한 번 눌러 저장하고, 나중에 "저장한 글 목록"에서 골라 원본 페이지 없이도 같은 모습으로 다시 보고 복사·다운로드·AI로 넘길 수 있습니다.

## 범위

1. **저장** — 변환 결과 화면의 내보내기 패널에 `저장` 버튼을 둡니다. 저장하면 그 시점의 제목, 저자(있을 때), 출처 주소, Markdown 본문이 내 저장한 글이 됩니다.
2. **중복 저장** — 같은 출처 주소를 다시 저장하면 새 항목을 만들지 않고 기존 항목을 최신 본문으로 갱신합니다. 주소당 한 건만 남습니다.
3. **비로그인 안내** — 로그인하지 않은 사용자도 `저장` 버튼은 보입니다. 누르면 "로그인하면 저장할 수 있어요" 안내와 로그인 링크를 보여줍니다.
4. **저장한 글 목록** — 로그인한 사용자 본인의 저장한 글을 저장한 시각 기준 최신순으로 보여줍니다. 각 항목에 제목, 저자(있을 때), 출처 도메인, 저장한 날짜를 표시합니다. 헤더에서 들어갑니다.
5. **저장한 글 보기** — 목록에서 항목을 누르면 변환 결과 화면과 같은 구성(제목·저자 헤더, 렌더링된 본문, 오른쪽 패널)으로 저장된 본문을 보여줍니다. 패널에는 복사하기, .md 다운로드, ChatGPT/Claude로 열기(프롬프트 선택 포함)가 있고, `저장` 대신 `삭제`가 있습니다. 출처 페이지로 가는 링크도 있습니다.
6. **삭제** — 목록과 글 보기에서 저장한 글을 삭제할 수 있고, 누르면 한 번 더 확인합니다.

## 수용 기준

- 로그인한 사용자가 변환 결과에서 `저장`을 누르면 성공 피드백이 보이고, 저장한 글 목록에 그 글이 맨 위에 나타납니다.
- 같은 주소를 다시 저장하면 목록에 항목이 늘지 않고, 보기 화면의 본문이 다시 저장한 시점의 내용으로 바뀝니다. 피드백은 갱신했다는 뜻이 드러납니다.
- 저장 중에는 진행 상태가 보이고 `저장` 버튼이 비활성화됩니다. 저장에 실패하면 원인을 알리는 오류 메시지를 보여주고, 변환 결과 화면은 그대로 남습니다.
- 로그인하지 않은 상태에서 `저장`을 누르면 저장되지 않고 로그인 안내와 링크가 보입니다. 로그인을 마치면 변환 화면으로 돌아오며, 방금 변환한 결과는 사라져 있어 다시 변환해야 합니다.
- 저장한 글 목록은 본인 글만 최신순으로 보여줍니다. 저장한 글이 없으면 빈 상태 안내와 변환 화면으로 가는 링크가 보입니다.
- 로그인하지 않은 상태로 저장한 글 목록이나 글 보기를 열면 로그인 화면으로 보내고, 로그인 뒤 원래 보려던 화면으로 돌아옵니다.
- 저장한 글 보기의 본문은 저장한 시점의 Markdown을 렌더링한 것과 같고, 복사하기·다운로드 결과는 저장된 원문 Markdown과 정확히 같습니다. 파일 이름 규칙, 프롬프트는 AI로 열기에만 붙는 규칙, URL/클립보드 전달 규칙은 변환 결과 화면과 같습니다.
- 삭제를 누르면 확인을 거친 뒤 삭제되고, 목록에서 사라집니다. 글 보기에서 삭제하면 목록으로 이동합니다. 삭제를 취소하면 아무것도 바뀌지 않습니다.
- 다른 사용자의 저장한 글은 목록에도 보이지 않고, 그 글의 보기 주소를 직접 열어도 볼 수 없으며 삭제하거나 갱신할 수도 없습니다. 존재하지 않는 글의 주소는 찾을 수 없다는 화면을 보여줍니다.
- 로그아웃한 뒤에는 저장한 글 목록과 글 보기를 열 수 없습니다.
- 좁은 화면에서도 목록, 글 보기, 패널의 모든 action이 유지되고, 패널은 본문 위로 올라가 한 열로 쌓입니다. 다크모드에서도 새 화면의 색이 읽힙니다.

## 확정된 제약과 이유

- **저장은 본문 사본을 남깁니다.** 원본 주소만 기억하고 다시 가져오는 방식이 아닙니다. 원본이 사라지거나 바뀌어도, 봇 차단으로 다시 못 가져와도 저장했던 글이 남아야 하기 때문입니다.
- **같은 주소는 한 건만 유지하고 다시 저장하면 갱신합니다.** 사용자가 정했습니다. 목록이 같은 글의 중복으로 길어지는 것을 막기 위함이며, 시점별 사본은 남기지 않습니다.
- **삭제를 포함합니다.** 사용자가 정했습니다. 잘못 저장한 글을 지울 방법이 없으면 목록이 정리되지 않고 쌓이기 때문입니다.
- **저장은 로그인한 사용자만 합니다.** 비로그인 사용자는 저장하지 못하고 로그인 안내를 받습니다. 사용자가 정했습니다. 로그인 후 방금 변환한 결과를 이어서 저장하는 복원은 하지 않습니다(결과를 브라우저에 임시로 들고 있어야 해 범위가 커집니다).
- **저장한 글은 본인만 읽고 갱신하고 삭제할 수 있습니다.** 인증된 서버 쪽 신원으로 판단하며, 화면 상태나 주소만으로 접근을 허용하지 않습니다. 기존 프로필의 소유자 전용 규칙과 같은 방식입니다.

## 가정(변경 가능)

- 저장한 글 목록의 주소는 `/saved`, 글 보기는 `/saved/<글 식별자>`를 씁니다.
- 목록은 페이지를 나누지 않고 전부 보여줍니다. 한 사용자의 저장한 글이 수십 건을 넘는 경우는 이 범위에서 다루지 않습니다.
- 헤더의 "계정" 링크 옆에 "저장한 글" 링크를 둡니다. 로그인 전에도 보이며, 누르면 로그인 화면으로 갑니다.
- 변환 결과 화면의 `저장` 버튼은 내보내기 패널 안에 두며, 이미 저장한 주소여도 라벨은 `저장` 그대로입니다. 누르면 갱신하고 피드백에서 갱신했다고 알립니다.
- 목록 항목은 Card 한 줄(제목, 저자·도메인, 저장 날짜, 삭제 버튼) 형태이고, 글 보기는 변환 결과 화면의 구성을 그대로 씁니다. 새 화면의 시안(prototype)은 만들지 않았고, 화면 구성은 이미 승인된 변환 결과 화면과 ui-composition 계약을 따릅니다.
- 삭제 확인은 shadcn의 확인 대화상자를 씁니다.
- 로그인 화면은 이전 화면으로 돌아가는 주소 규칙(`next`)을 이미 지원하므로, 저장 안내의 로그인 링크는 변환 화면(`/`)으로 돌아오게 합니다.

## 다루지 않는 것

- 저장한 글 검색, 정렬 변경, 태그·폴더·메모, 즐겨찾기.
- 저장한 글 편집(제목·본문 수정).
- 저장한 글 공유, 공개 주소.
- 시점별 사본(버전) 보관, 저장한 뒤 원본 변경 감지.
- 로그인 후 방금 변환한 결과를 이어서 자동 저장하는 흐름.
- 비로그인(브라우저 로컬) 저장.
- 한 사용자가 저장할 수 있는 글 수 제한, 목록 페이지 나누기.

## 남은 위험

- 저장한 본문은 제3자 웹 페이지의 내용 사본입니다. 개인이 자기 계정에 남기는 용도로 정했지만, 공개하거나 공유하는 기능은 이 범위에 없습니다. 이후 공유를 붙일 때는 저작권과 출처 표시를 다시 정해야 합니다.
- 아주 긴 글(수 MB)을 저장하면 저장과 목록 불러오기가 느려질 수 있습니다. 변환 쪽 응답 한도(5MB)를 넘는 본문은 애초에 만들어지지 않습니다. 목록은 본문 없이 제목·저자·도메인·날짜만 불러와야 합니다.
- 목록에 페이지 나누기가 없어서 저장한 글이 매우 많아지면 목록이 길어집니다.
- Vercel 환경변수가 빠진 배포에서는 로그인과 저장이 모두 동작하지 않습니다(기존 로그인 기능과 같은 전제).
